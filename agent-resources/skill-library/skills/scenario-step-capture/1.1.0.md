# 场景步骤采集

## 目的

将完整用户旅程与关注的性能窗口分开表达，复用前置操作，把目标步骤的运行数据交给并行建模。

## 方法

1. 从页面 `scenario_capture` 上下文获取操作说明、选中步骤、`connection_mode` 和设备选择，调用 `scenario_capture_catalog` 读取图库 17 步模板、profile、连接方式和本机 HDC 状态。沿用页面选定方式；尚未选择时采用 catalog 的 `default_connection_mode`，运行在 Mac 上的平台默认为 `local`。
2. 调用 `scenario_capture_discover_devices(connection_mode="local")` 发现平台服务所在电脑直连的设备。使用远端 Windows 主机时，传入 `connection_mode="bridge"` 与选定的 `bridge_id`。将发现结果与用户选择的设备序列号对应起来。
3. 将每步表达为 step_id、title、operation、target、expected_targets；用 profile.targets 描述文本、资源 ID 或相对坐标定位。保留用户的自然语言说明；结合 UI 层级和用户提供的定位信息补齐操作。已有图库流程复用模板和选择器。
4. 将关注窗口写入 capture.selected_step_ids；preparation_mode=auto 从开头执行前置步骤，already_prepared 从首个选中步骤开始。为 Trace、HiLog 和 PMU 设置采集器、采样周期及事件组，采用同一设备单调时钟记录步骤边界。
5. 调用 `scenario_capture_create_plan(plan)` 保存版本，通过 `scenario_capture_read_plan` 查看完整计划与定位信息。调用 `scenario_capture_generate_script` 输出包含计划的 Python 自动化脚本；本机直连运行参数为 `--connection-mode local --device-serial <serial>`，远端连接参数为 `--connection-mode bridge --bridge-id <id> --device-serial <serial>`。
6. 用户发起采集任务时调用 `scenario_capture_execute`，传入 `plan_id`、`device_serial` 与选定的 `connection_mode`，Bridge 模式同时传入 `bridge_id`。通过 `parallel_job_read` 跟踪进度；`scenario_capture_read_run` 汇总连接方式、目标步骤、文件、采集覆盖和运行信息。需要停止时调用 `parallel_job_cancel`；用户重新采集同一计划时，以新的 `retry_nonce` 标识新批次。
7. 用户继续建模时，将 capture_run_id、step_id 和目标线程/帧传给 `parallel_modeling_import_dataset`。

## 交付

结构化步骤与采集计划、可下载 Python、批次标识、连接方式与设备身份、Trace/HiLog/PMU 文件清单和哈希、步骤时间窗口、采集质量说明。清楚呈现实际采到的事件、可用计数以及后续建模所需输入。
