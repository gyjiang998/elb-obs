# 场景步骤采集

## 目的

将完整用户旅程与关注的性能窗口分开表达，由平台运行时处理连接、屏幕准备和前置操作，把目标步骤的运行数据交给并行建模。

## 方法

1. 从页面 `scenario_capture` 上下文读取操作说明、选中步骤与当前目标设备。调用 `scenario_capture_catalog` 获取图库 17 步模板、profile 与采集能力。
2. 使用 `scenario_capture_discover_devices()` 自动发现设备：优先本机实际连接的设备，未发现时检查当前项目在线 Windows Bridge。使用返回的 `selected_device`；多个候选时让用户选择目标设备。页面已有选择时沿用该设备及连接路径，断开时提示重连同一设备。
3. 将每步表达为 step_id、title、operation、target、expected_targets；用 profile.targets 描述文本、资源 ID 或相对坐标定位。保留自然语言说明，结合 UI 层级补齐操作，图库流程复用模板和选择器。
4. 将关注窗口写入 capture.selected_step_ids；preparation_mode=auto 自动准备至目标步骤，already_prepared 从首个选中步骤开始。为 Trace、HiLog 与 PMU 设置采集器、采样周期及事件组，用设备单调时钟记录步骤边界。
5. 调用 `scenario_capture_create_plan(plan)` 保存版本，使用 `scenario_capture_read_plan` 查看完整计划，调用 `scenario_capture_generate_script` 输出 Python。脚本默认自动选连接；唯一设备时运行 `python capture_scenario.py --platform <平台地址>` 即可，多设备时用 `--device-serial <序列号>` 指定目标。
6. 用户发起采集时调用 `scenario_capture_execute`，传入 plan_id，采用默认 auto；已有目标设备时同时传其 device_serial 和 bridge_id。设备租约与屏幕准备交由平台运行时完成。通过 `parallel_job_read` 跟踪进度，`scenario_capture_read_run` 汇总步骤、文件与质量。停止时调用 `parallel_job_cancel`，重新采集以新的 retry_nonce 标识新批次。
7. 用户继续建模时，将 capture_run_id、step_id 与目标线程/帧传给 `parallel_modeling_import_dataset`。

## 采集前设备准备与远程诊断

- 平台先通过 `power-shell wakeup` 亮屏，再读取新鲜 UI 布局判断设备状态。确认无密码锁屏后，尝试返回键关闭锁屏页；标准命令为 `uitest uiInput keyEvent Back`，设备解析器不接受标准形式时由运行时选择兼容形式。仍处于已识别锁屏时，再按实际屏幕尺寸进行有限次上滑，每次操作后重新读布局确认状态。凭据输入界面对应设备认证，由认证完成后的新布局确认可继续采集。
- 识别到 USB 连接方式选择框时，平台通过返回键收起弹窗，读取新布局并确认目标页面后启动采集器；这一步用于关闭遮挡层，保持当前连接方式。已准备好的目标页面沿用当前状态；界面识别不明时，依靠现场布局与截图决定下一步。
- 用户无法看到手机时，优先读取本次采集结果中的设备准备记录、命令及返回结果、最新布局和 `screen_preparation_screenshot`，引导查看页面“失败现场”。根据实际记录区分亮屏失败、返回键解析失败、锁屏或 USB 弹窗未消失、目标页面未就绪；以平台本次运行的观察说明结果与下一步。

## 交付

结构化采集计划、可下载 Python、批次标识、自动识别的连接方式与设备身份、文件清单与哈希、步骤时间窗口和数据质量说明；准备失败时附现场诊断与截图获取结果。
