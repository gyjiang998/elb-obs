# Trace 热点代码深挖

目标是从 trace 边界找到“值得继续优化分析的最小代码候选”，不是把桩点所在函数自动宣布为热点。

1. 先校准时间语义：stage duration 是阶段包络；事件 duration 默认是 inclusive span。没有 Hiperf、CPU sample、嵌套 self-time 或等价证据时，不得给桩点函数或 callee 分配耗时、占比或排名。
2. 先定位 event label 的插桩行和包围函数，只记为 `trace_anchor_function`。若当前任务绑定 ready 代码底图，加载 `code-context-retrieval`，以 event、包围函数和模块职责查询语义图，获得值得核对的 caller/callee/外部边界候选。
3. 使用原生代码工具和真实编译上下文验证局部区域、caller、直接或必要的传递 callee、虚调用/函数指针目标及源码外 runtime/model/driver 边界。优先 Clang AST、CFG、compile_commands；缺失时用 `rg` 与精确源码行。不要固定调用深度，语义图关系不能替代源码调用点。
4. 独立比较候选与 trace 边界的关联、实际执行可能性、源码成本信号和可优化范围。规则循环、批量访存、重计算、分配/拷贝、锁/等待/IPC、硬件提交升权；普通日志、错误分支、getter 和薄 wrapper 降权。
5. 每条判断标明 `trace_observed`、`source_observed`、`model_hypothesis` 或 `unresolved`。无采样时“它最热”仍是 `model_hypothesis_without_cpu_sampling`。
6. 当前仓没有实现时保留 `external_runtime_or_model_boundary`，列出所需 runtime 源码、模型图/算子 profile、调用栈或采样证据，不用同名 wrapper、声明或相邻代码代替实现。
7. 找到源码可观察的最小候选后，调用 `reasoning.select_hotspot_source_candidate` 提交精确 path、行范围、candidate_kind、relation_to_anchor、rationale 和可复核 call_path。该 action 不会把模型假设升级成采样事实。
8. 没有可提交候选时停止在 `evidence_required`，不要继续硬件路由；有多个合理分支时保留少量候选和区分它们所需的最小证据。

用中文说明 trace、语义图、源码和模型推断分别证明了什么。
