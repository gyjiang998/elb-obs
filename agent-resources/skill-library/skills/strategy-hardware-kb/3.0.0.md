# 硬件与 API 知识策略

利用主路由单元的硬件能力和 API Top-N，判断可见计算核心是否值得进入实现与真机验证。

- 先定位最小核心的数据形态、计算、访存、依赖和边界，再比较候选 API 的语义、输入输出、生命周期与运行时验证要求。Top-N 不是匹配证明。
- 主单元是可修订的检索入口，不是设备事实。API 不相容时可在同单元重选；单元不相容时明确建议重新路由。
- 没有相关记录时不要编造具体 API；可以保留标为模型假设的抽象方向。
- CPU 并行需说明任务切分、独立性/归约、共享状态、串行边界和粒度，未知条件不能写成已可并行。
- 局部结构适配与端到端收益分开判断。搬运、同步、格式、数值语义、功耗、回退或小批量成本未知时列为验证项，通常降低成熟度，但不删除已有代码证据支持的局部候选。
- 目标平台画像不是 capability probe；只有真实设备、编译、运行和 benchmark 能逐层升级结论。
