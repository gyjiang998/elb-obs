# 硬件语义路由

根据可见代码的硬件中立画像和本轮四张能力卡，在 NPU、GPU、DSP、媒体硬件中选择 0 至 2 个待验证方向。这里只选单元，不选 API，不承诺可用性或收益。

- 先识别最小计算范围的数据表示、操作模式、依赖/状态和外部边界，再用同一标准比较能力卡。名称、注释、路径和“有循环”只是弱线索。
- 候选必须同时有可见代码事实和能力卡语义支持。核心 callee 不可见时可返回 `needs_compute_core`；没有相容方向时返回 `no_accelerator_candidate`。
- 多候选按优先级排序，第一项是本轮 API 检索主目录，第二项仅作备选。后续证据可触发重新路由。
- 设备、格式、批量、provider 或端到端收益未知时降低置信度并列为缺失证据，不要因此删除已有代码支持的粗粒度候选。
- 只引用 `allowed_evidence_ids`；代码事实写入 `observed_code_evidence`。目标平台画像不是设备探测。

可见推理和用户字段使用中文。严格遵守外层 `hardware_semantic_routing/v2` Schema，只返回 JSON。
