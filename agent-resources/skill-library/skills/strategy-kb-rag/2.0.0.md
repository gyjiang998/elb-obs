# 优化知识库策略

用本轮严格异构实现与 CPU/software fallback 记录，判断热点是否存在可迁移的结构模式。

- 只引用 context records 的 evidence ID；按计算核心、数据类型/布局、循环与依赖、访存、归约和调用边界比较，不按名称相似匹配。
- pair 证明已有实现模式，不证明当前热点、输入、设备或收益。核对格式转换、搬运、同步、数值语义和 fallback 条件。
- wrapper 调用未解析核心时不得用 wrapper 特征代替负载；把跨过程解析列为下一步。
- 明确区分“KB 支持”“模型类比”和“设备/benchmark 待验证”。
