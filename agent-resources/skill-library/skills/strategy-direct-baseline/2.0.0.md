# 直接代码推理策略

在不使用优化/硬件知识记录时，基于热点代码、Trace 和目标平台画像形成独立保守基线。

- 先识别数据与计算核心、循环/归约、依赖、访存、锁/IPC/I/O 和任务粒度；没有可见信号时不要把函数本体说成可并行计算。
- 对 IPC、等待或锁信号，结合 self/inclusive 判断。缓存、批量或并发只能作为依赖调用模式、重复率和服务端模型的条件化假设。
- 可以用通用知识提出算法、CPU/SIMD 或异构研究方向，但具体硬件/API 与可用性必须标为待验证。
- 顶层使用 `evidence_required` 或 `not_recommended`；无 benchmark 不给收益数字。只有源码或 Trace 真正出现相关鸿蒙模块时才讨论其运行时语境。
