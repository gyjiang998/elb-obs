# BuildItem 并行建模

## 目的

将实际场景负载转为可计算的任务依赖图，把阶段计算、访存和调度特征与单任务核频成本、多任务共跑干扰结合，回答怎样并行、如何放核、预计收益多少。

## 方法

1. 从页面 `parallel_modeling` 上下文读取数据集、`model_package_id`、`feature_profile_id`、候选阶段和搜索空间。使用 `parallel_modeling_catalog` 读取实际可用模型和硬件；用 `parallel_modeling_import_dataset` 导入归档、采集批次或解析结果。数据身份与真实 UI callback 对齐，硬件画像用于限定搜索域。
2. 使用已选的负载特征版本。需要建立版本时，通过 `workload_features_catalog` 读取指标合同，调用 `workload_features_analyze(dataset_id)`，再用 `workload_features_read_profile` 查看阶段指标、采样上下界、分型依据与缺失项。计算 / 访存类别是实测证据支持的候选描述，共跑收益来自相应校准模型。
3. 调用 `parallel_modeling_analyze(dataset_id, model_package_id, feature_profile_id)`，用 `parallel_job_read` 跟踪任务，通过 `parallel_modeling_read_analysis` 读取 BuildItem、同步服务、运行 / 等待账本和回放结果。以 `replay_gate.passed` 评估账目一致性，按页面选择传递 `candidate_ids`。`preserve_observed` 保留组件内顺序、请求返回依赖、未并行工作与服务争用；仿真采用公共 fork 输入就绪、组件独立执行、公共 join 消费结果的条件假设。
4. 调用 `parallel_modeling_search(search)`，传递 `analysis_id/model_package_id/feature_profile_id/candidate_ids/objective/space`。`minimum_latency` 搜索最低时延；`minimum_frequency_with_budget` 在 `budget_ms` 内优先较低的核组共享频点。`space` 使用 `available_core_group_ids`、`main_core_group_id`、`worker_counts`、`main_participation`、`frequency_policy`，可用 `frequencies_khz` 限定频点；0 worker 表示串行对照。同核组共享频率，worker 位于同一核组。需要敏感性结果时设置 `robustness=true`，按返回的实际情景数说明覆盖。
5. 通过 `parallel_job_read` 和 `parallel_modeling_read_search` 获取推荐配置与候选排序。分别说明单任务成本、双任务定向干扰矩阵、动态并发数、启动成本和依赖 / 服务等待如何影响终点。读取每个候选的 `interference`：校准覆盖的 CPU 时间、匹配单元格、通用争用回退及原因，结合模型中的核组、频点、工作集、代理负载适用域解释收益。

## 交付

推荐 worker 数、主线程参与方式、核组和频率、UI 回调预测耗时、相对实测基线的收益、所用特征与校准版本，以及搜索覆盖。频率字段为 kHz，应用 / 服务 core-ms 表示 CPU 占用。区分实测账目、代理负载校准和应用条件预测；逐阶段 PMU 保留来源与边界，缺失指标显式展示。同步回填页面保存的分析和搜索结果，使用户可继续比较或调整配置。
