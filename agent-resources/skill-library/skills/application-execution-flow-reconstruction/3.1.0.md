# 应用执行流程重建

`code-context-retrieval` 提供可选的代码底图导航。`source_scopes` 是全部代码仓范围；Agent 根据用户、Trace、符号和路径线索，组合底图与原生源码工具跨仓串联。平台工具负责工件、投影和证据校验。

## 完整操作候选

1. 将目标整理为初始状态、有序用户动作、可观察结果及包含/排除边界。候选覆盖完整旅程，单个函数、接口或回调只作实现证据。
2. 每个 source scope 有匹配当前快照的 ready 底图时，可用 `code_graph_query_knowledge` 快速发现候选；已有强线索、底图缺失或召回不足时，使用 Agent 原生搜索、LSP、编译上下文和源码阅读定位入口、跨模块转发与完成边界。底图候选经源码复核后形成静态结论。每个动作提交 `action_coverage`，并说明当前缺口和疑似模块。
3. 候选数量按真实边界差异决定，不固定为 3。调用 `application_flow_publish_candidates`，原样提交 `source_scopes`、`operation_scope="complete_user_operation"`、完整操作蓝图和已核对入口/出口；不要手写完整 discovery。

## 分层阶段图

读取用户确认的 flow，按“用户动作 → 业务大阶段 → 可定位子阶段 → 函数实现”生成一份完整 Mermaid。每个 `@stage` 有 hierarchy 绑定和已核对 implementation；跨仓实现带 `source_connector_id`。调用 `application_flow_compile_mermaid`，由工具投影为稳定 `application-flow-scenario/v2`，不要手写 JSON。

修订场景时读取当前工件，只重查受影响部分，并传 `parent_scenario_artifact_id` 和 `revision_request`。

## 源码 HiTrace

对每个 implementation 调用 `application_flow_inspect_trace_instrumentation`，核对直接 API、模块宏、包装函数、RAII 和 ArkTS Trace 调用。字面量提交真实 label，格式化事件提交静态前缀，`__func__` / `__PRETTY_FUNCTION__` 派生事件提交稳定 selector；最后一次调用 `application_flow_enrich_trace_anchors`。源码命中只证明插桩声明存在。

## 真实 Trace 校准

用户选定 `.htrace` 或阶段分析 JSON 后，读取当前场景并调用 `application_flow_inspect_runtime_trace`。工具返回真实 event name、运行上下文、时间范围及有界候选；检索分数仅用于缩小范围。

结合动作、阶段语义、implementation、源码锚点和运行时时序判断 start/end。同步 scope 可同时承担 start/end；证据不足保留 `partial` 或 `unmatched`。Trace 暴露图结构偏差时可以修订完整分层 Mermaid。

调用 `application_flow_apply_runtime_trace_alignment`，逐阶段引用目录中的真实 `event_id`，提交变更摘要和限制。运行时匹配写入场景侧车；Mermaid 元数据和最终 `application-flow-scenario/v2` JSON Schema 保持不变。
