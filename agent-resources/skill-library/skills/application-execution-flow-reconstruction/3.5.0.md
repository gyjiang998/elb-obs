# 应用执行流程重建

## 目的

理解用户描述的完整操作，找到它在多个模块中的主要执行链，将其组织为“用户动作 → 业务大阶段 → 可定位子阶段 → 函数实现”的分层流程图。结果既要便于人理解，也要能继续关联 HiTrace、定位热点和迭代修订。

Agent 负责判断合理的操作边界、阶段粒度、源码探索路径和工具组合。优先形成一份有用且诚实的整体解释；源码范围不足、调用关系不确定或运行时证据缺失时，在结果中明确暴露缺口。

## 输入

- 用户描述的操作、初始状态、关注边界及预期可观察结果。
- `source_scopes`：本轮可分析的一个或多个代码仓、目录和源码快照。
- 可选代码知识底图：用于快速导航符号、调用候选和插桩位置。
- 可选 `.htrace` 或阶段分析 JSON：用于校准实际执行结构和阶段边界。
- 修订任务还会提供既有 `scenario_artifact_id`、Mermaid、JSON 和用户反馈。

## 交付结果

- 一份覆盖完整用户操作的 Mermaid。作者层保留 `@action`、`@phase`、`@stage` 和 `@stage_hierarchy`；已从源码核对的实现使用 `@implementation` 记录符号、路径、行号、关系及跨仓 `source_connector_id`。
- 暂时无法落到当前源码范围的阶段仍可保留在图中，其实现缺口进入 `unknowns` 和页面小结，供用户补充代码仓或修改边界。
- `application_flow_compile_mermaid` 将 Mermaid 投影为字段稳定的 `application-flow-scenario/v2` JSON，并保存分层结构。完成真实 Trace 校准后，平台还会生成符合 `application-flow-stage-analysis-v1.schema.json` 的侧车，提供阶段墙钟包络、阶段内事件统计和热点预览；Agent 无需手工计算时长。
- 场景证据说明源码实现覆盖、HiTrace 插桩、真实 Trace 边界和未决问题。源码声明、静态调用候选与运行时观察保持各自证据层级。

## 分析能力

Agent 可以按当前线索组合原生源码搜索、阅读、LSP、调用关系分析和代码底图查询。代码底图适合缩小范围，真实源码适合确认实现；任何一种未命中都可以换用其他代码理解路径继续探索。

`application_flow_inspect_trace_instrumentation` 可快速识别直接 API、模块宏、包装函数、RAII 与 ArkTS Trace 调用。复杂包装或工具召回不足时，Agent 可直接沿定义、调用参数和生命周期读取源码，再通过 `application_flow_enrich_trace_anchors` 保存确认结果。

真实 Trace 可用于验证、拆分、合并或重排静态阶段。运行时确认的 start/end 使用事件目录中的完整 `event_name`，匹配方式为 `exact`；部分匹配事件保存在 supporting evidence 中，未闭合阶段保留 `matcher: unavailable`。

## 平台工件

当前场景 Schema 通过 discovery 建立来源血缘。首次分析形成整体判断后，使用 `application_flow_publish_candidates` 将模型选定的一个完整操作登记为内部分析记录，并把动作覆盖与源码缺口写入 `action_coverage`；页面不再设置候选确认步骤。随后使用返回的 `discovery_artifact_id` 和 `flow_id` 发布阶段图。

源码插桩结果通过 `application_flow_enrich_trace_anchors` 进入场景证据；存在真实 Trace 时，通过 `application_flow_inspect_runtime_trace` 与 `application_flow_apply_runtime_trace_alignment` 保存运行时校准并生成阶段负载分析。工具负责字段校验、JSON 投影、时长统计和版本血缘，Agent 负责语义理解与最终判断。

修订已有结果时，以当前场景和用户反馈为上下文，自主确定需要重读的源码与边界；发布新 Mermaid 时携带 `parent_scenario_artifact_id` 和 `revision_request`，保留旧版本。
