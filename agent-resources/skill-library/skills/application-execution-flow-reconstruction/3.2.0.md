# 应用执行流程重建

`code-context-retrieval` 提供可选的代码底图导航。`source_scopes` 是全部代码仓范围；Agent 根据用户、Trace、符号和路径线索，组合底图与原生源码工具跨仓串联。平台工具负责工件、投影和证据校验。

## 完整操作候选

1. 将目标整理为初始状态、有序用户动作、可观察结果及包含/排除边界。候选覆盖完整旅程，单个函数、接口或回调只作实现证据。
2. 当前快照有可用底图时，可用 `code_graph_query_knowledge` 快速发现候选；已有强线索、底图缺失或召回不足时，使用 Agent 原生搜索、LSP、编译上下文和源码阅读定位入口、跨模块转发与完成边界。每个动作提交 `action_coverage`，并说明当前缺口和疑似模块。
3. 候选数量按真实边界差异决定，不固定为 3。调用 `application_flow_publish_candidates`，原样提交 `source_scopes`、`operation_scope="complete_user_operation"`、完整操作蓝图和已核对入口/出口。

## 阶段图与证据校准

用户确认 flow 后，在一次连续任务中复用同一轮细粒度代码理解：

1. 按“用户动作 → 业务大阶段 → 可定位子阶段 → 函数实现”生成完整 Mermaid。每个 `@stage` 有 hierarchy 绑定和已核对 implementation；跨仓实现带 `source_connector_id`。先调用 `application_flow_compile_mermaid` 获得场景工件，标准 `application-flow-scenario/v2` JSON 由工具生成。
2. 沿每个 implementation 及相邻函数链调用 `application_flow_inspect_trace_instrumentation`，识别直接 API、模块宏、包装函数、RAII 和 ArkTS Trace 调用。字面量记录 label，格式化事件记录静态前缀，`__func__` / `__PRETTY_FUNCTION__` 派生事件记录稳定 selector。汇总全部阶段后调用一次 `application_flow_enrich_trace_anchors`；源码结果表示插桩声明证据。
3. 本轮选择了 `.htrace` 或阶段分析 JSON 时，以上一步增强场景调用 `application_flow_inspect_runtime_trace`。结合阶段语义、implementation、源码插桩、进程线程和时序判断边界；真实 Trace 也可支持阶段拆分、合并、重排或改名。
4. 运行时确认的 start/end 使用事件目录中完整的 `event_name`，Mermaid 写作 `trace_point "<完整 event_name>" exact in <process_group>`，编译后的 JSON `name_match` 为 `exact`。完整闭合的阶段引用 start/end `event_id`；只有候选而未闭合的阶段保留 `matcher: unavailable`，候选通过 `supporting_event_ids` 记录。函数名和源码 selector 只有在事件目录出现相同完整名称时才成为运行时边界。
5. 调用 `application_flow_apply_runtime_trace_alignment` 生成最终校准版本。未选择真实 Trace 时，以源码锚点增强版本作为本轮结果，并明确其证据范围是源码声明。

最终产物始终是完整 Mermaid 与工具生成的既有 `application-flow-scenario/v2` JSON；运行时匹配保存在场景证据侧车，Schema 保持不变。

修订场景时读取当前工件，只重查受影响的代码和边界，并执行同一条生成与校准链；传入 `parent_scenario_artifact_id` 和 `revision_request` 保留版本关系。
