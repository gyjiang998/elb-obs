# 应用执行流程重建

这是 focused task，不进入热点优化或真机流程。历史样本只定义字段格式，不能提供当前业务事实。

## 发现

1. 使用 `repository-context.json.source_scope` 和 Kimi 原生 `Glob/Grep/Read/Bash` 探索源码；平台 MCP 用于工件和校验，不替代代码导航。
2. 先调用一次 `application_flow_inspect_repository` 获取入口线索。必要时补一次聚焦批量搜索，不展开完整调用链或全仓 HiTrace。
3. 默认整理 3 个候选，每个只需入口、完成语义、参与者及可复核路径/行号/符号。调用 `application_flow_publish_candidates` 后立即停止，等待用户选择。

## 生成

1. 用 `application_flow_read_asset` 读取选中的 artifact/flow_id，只深入这一条流程。
2. 重建调用链、状态/IPC/回调边界，并从源码追踪 HiTrace 原语或包装宏。新增证据保存为聚焦 discovery。
3. 按 `references/application-flow-scenario-v2.schema.json` 生成场景 JSON；`id`、`name`、`process_name`、`order`、`optional`、`start`、`end`、`matcher` 等属性名不可改。
4. 生成与 JSON stage 一一对应的 Mermaid，并调用 `application_flow_save_scenario` 校验保存。

`observed_in_source` 必须有精确源码位置、插桩宏、event 匹配和构建条件，并闭合 stage 的 start/end；否则保持 `draft_needs_trace_evidence`。源码插桩只证明声明存在，不证明运行发生、时序、关键路径或耗时。需要定位表达式细节时读取 `references/application-flow-scenario-contract.md`。
