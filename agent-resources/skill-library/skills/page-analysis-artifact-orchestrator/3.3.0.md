# 页面分析工件

1. 新代码先用页面给出的 `input_id` 绑定为热点，取得真实 `analysis_id` 与代码工件；已绑定热点从当前阶段继续。
2. 直接调用 `reasoning_prepare_hardware_semantic_route`，按返回的 output_contract 形成路由，再调用 `reasoning_run_hardware_semantic_route` 保存。
3. 直接调用 `reasoning_prepare_context`，按返回的 output_contract 形成机会数组，再调用 `reasoning_run_strategy` 保存。
4. 上述名称是真实 MCP 工具，不是待搜索的源码符号或页面 Action ID；不得为调用它们先执行 `ls`、`grep` 或加载 Action 目录。
5. 输出契约是硬边界：机会写入 `opportunities` 数组，`analysis_scope` 保持对象；不要改用自定义字段。
6. action 失败时依据诊断修订。聊天结论、prepare 工件和真机实验不能冒充缺失的页面工件。

后续可补源码、重选 API、重新路由或进入真机验证，不设固定推理轮次。
