# 页面分析工件

目标是让页面状态与 Agent 已完成的事实一致。

1. 新代码先通过浏览器授权的 `input_id` 和冻结范围绑定为热点，等待真实 `analysis_id` 与代码工件。
2. 调用 `reasoning.prepare_hardware_semantic_route`，在当前 Session 形成规定 Schema 的路由，再用 `reasoning.run_hardware_semantic_route` 保存回填。
3. 调用 `reasoning.prepare_context`，在当前 Session 形成机会结果，再用 `reasoning.run_strategy` 校验保存。
4. 后续可解析 callee、重选 API、重新路由或进入真机验证；不设固定轮次。
5. action 失败时修正其明确诊断。聊天结论、prepare 工件和真机实验都不能冒充缺失的页面阶段工件。
