# 页面分析工件

1. 新代码先用页面给出的 `input_id` 绑定为热点，取得真实 `analysis_id` 与代码工件。
2. 直接调用 `reasoning.prepare_hardware_semantic_route`；按其 output_contract 在当前 Session 形成路由，再调用 `reasoning.run_hardware_semantic_route` 保存。
3. 直接调用 `reasoning.prepare_context`；按其 output_contract 在当前 Session 形成机会数组，再调用 `reasoning.run_strategy` 保存。
4. prepare 与 run 的 action ID 和参数已经明确，不要先调用 `platform_list_page_actions`。只有未登记的新路径才精确查询动作。
5. 输出契约是硬边界：机会必须写入 `opportunities` 数组，`analysis_scope` 必须是对象；不要改用 primary/secondary 等自定义字段。
6. action 失败时依据诊断修订。聊天结论、prepare 工件和真机实验都不能冒充缺失的页面工件。

后续可补源码、重选 API、重新路由或进入真机验证，不设固定推理轮次。
