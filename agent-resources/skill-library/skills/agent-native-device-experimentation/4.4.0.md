# 真机迭代验证

验证一个明确主张，而不是生成展示代码。

- 使用任务包中的热点、策略、目标单元和已有事实；引用 ID 不是路径。目标单元、API 和模板都是可修订假设，真实结果否定时可重选或重新路由。
- 按依赖图推进：本机设备分支为 `device.discover -> device.probe`；Windows Bridge 分支为 `device.list_bridges -> device.discover -> device.create_lease -> device.probe`，构建分支为 `模板选择 -> build.describe_profile -> build.stage_source -> build.create`。仅 `device.deploy_artifact` 同时依赖 probe 与成功 build，随后才是 `device.execute_shell`。
- 设备租约是平台并发控制状态，不是需要模型反复推理的业务证据。长时间构建期间租约过期时，平台会让旧 ID 安全指向新的有效租约并在 action 结果返回 `lease_resolution`；继续使用真实返回即可，不得因旧 checkpoint 中的租约时间戳重做构建、probe 或反复提交同一个换租请求。
- 设备分支与构建分支互不等待。运行时支持并发工具时并发推进；只能串行调用时，取得真实设备 serial 后先完成快速的构建面查询，再执行可能等待远端 Bridge 的 `device.probe`。probe 失败或超时不抹掉构建分支事实。
- 先用 `platform_list_hardware_api_templates` 选择语义和 profile 相容的模板，再以精确 ID 读取。Agent Adapter 未直接展示专用工具时，通过 `platform_call_tool` 传入同一工具名与参数。保留稳定脚手架，替换当前计算核心、输入合同、CPU oracle 和比较逻辑；模板历史不是本轮证据。
- 按 API 暴露层选择官方测试承载。只有真实 runner 报告才能声称使用了 xDevice/Hypium/HATS；没有 runner 时可做 `standalone_fallback`。
- 首个实验只闭合最小未知量：确定性输入、CPU/software reference、候选路径、结果比较和明确退出码。功能等价后再测代表性规模和性能。
- 每次只依据真实 profile、编译、链接、上传、stdout/stderr 或设备观察做最小修订；不要猜头文件、库、动态 ID 或设备能力，不重复无新增事实的失败调用。
- 任务完成、方向被证伪、环境明确不可执行、用户停止或缺少用户专有输入时结束。

最终分别报告模板/承载、构建、部署、设备执行、功能等价、目标硬件参与、热点集成、性能/功耗和限制。需要框架选择细节时读取 `references/official-test-frameworks.md`。
