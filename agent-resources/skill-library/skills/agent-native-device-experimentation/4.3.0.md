# 真机迭代验证

验证一个明确主张，而不是生成展示代码。

- 使用任务包中的热点、策略、目标单元和已有事实；引用 ID 不是路径。目标单元、API 和模板都是可修订假设，真实结果否定时可重选或重新路由。
- 按依赖图推进，而不是把页面阶段当作线性门禁：本机设备分支为 `device.discover -> device.probe`；Windows Bridge 分支为 `device.list_bridges -> device.discover -> device.create_lease -> device.probe`（任务已提供 Bridge 时可跳过选择）；构建分支为 `模板选择 -> build.describe_profile -> build.stage_source -> build.create`。仅 `device.deploy_artifact` 同时依赖 probe 与成功 build，随后才是 `device.execute_shell`。
- 设备分支与构建分支互不等待。运行时支持并发工具时并发推进；只能串行调用时，取得真实设备 serial 后先完成快速的 `build.describe_profile`，再执行可能等待远端 Bridge 的 `device.probe`。probe 失败或超时不抹掉构建分支事实，也不得机械重复同一调用。
- 先用 `platform_list_hardware_api_templates` 选择语义和 profile 相容的模板，再以精确 ID 读取。保留稳定脚手架，替换当前计算核心、输入合同、CPU oracle 和比较逻辑；模板历史不是本轮证据。
- 按 API 暴露层选择官方测试承载。只有真实 runner 报告才能声称使用了 xDevice/Hypium/HATS；没有 runner 时可做 `standalone_fallback`。
- 首个实验只闭合最小未知量：确定性输入、CPU/software reference、候选路径、结果比较和明确退出码。功能等价后再测代表性规模和性能。
- 每次只依据真实 profile、编译、链接、上传、stdout/stderr 或设备观察做最小修订；不要猜头文件、库、动态 ID 或设备能力，不重复无新增事实的失败调用。
- 任务完成、方向被证伪、环境明确不可执行、用户停止或缺少用户专有输入时结束。

最终分别报告模板/承载、构建、部署、设备执行、功能等价、目标硬件参与、热点集成、性能/功耗和限制。需要框架选择细节时读取 `references/official-test-frameworks.md`。
