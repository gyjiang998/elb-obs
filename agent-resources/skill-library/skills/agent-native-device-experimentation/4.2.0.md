# 真机迭代验证

验证一个明确主张，而不是生成展示代码。

- 使用任务包中的热点、策略、目标单元和已有 probe；引用 ID 不是路径。目标单元/API 是可修订假设，事实否定时可重选 API 或重新路由。
- 先用 `platform_list_hardware_api_templates` 选择语义和 profile 相容的模板，再以精确 ID 读取。保留稳定脚手架，替换当前计算核心、输入合同、CPU oracle 和比较逻辑；模板历史不是本轮证据。
- 按 API 暴露层选择官方测试承载。只有真实 runner 报告才能声称使用了 xDevice/Hypium/HATS；没有 runner 时可做 `standalone_fallback`。
- 后端文件、Shell、编译和同机 HDC 可直接使用；需要可复现固定环境时使用 profile -> stage -> build -> deploy -> execute 工件链。Windows 设备使用 Device Bridge。
- 首个实验只闭合最小未知量：确定性输入、CPU/software reference、候选路径、结果比较和明确退出码。功能等价后再测代表性规模和性能。
- 每次只依据真实编译、链接、上传、stdout/stderr 或设备观察做最小修订；不要猜头文件、库、动态 ID 或设备能力，不重复无新增事实的失败调用。
- 任务完成、方向被证伪、环境明确不可执行、用户停止或缺少用户专有输入时结束。

最终分别报告模板/承载、构建、部署、设备执行、功能等价、目标硬件参与、热点集成、性能/功耗和限制。需要框架选择细节时读取 `references/official-test-frameworks.md`。
