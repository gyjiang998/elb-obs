# 真机迭代验证

验证一个明确主张。

- 使用任务包中的热点、策略、目标单元和已有事实。目标单元、API 和模板都是可修订假设，真实结果否定时可重选或重新路由。
- 按依赖图推进：本机设备分支为 `device.discover -> device.probe`；Windows Bridge 分支为 `device.list_bridges -> device.discover -> device.probe`，构建分支为 `模板选择 -> build.describe_profile -> build.stage_source -> build.create`。仅 `device.deploy_artifact` 同时依赖 probe 与成功 build，随后才是 `device.execute_shell`。
- 依据用户选择或发现的唯一候选确认 `bridge_id`、`logical_device_id` 与 serial，多个候选先确认目标。远程动作可省略 `device_lease_id`，由平台自动创建或复用单写租约；`device.create_lease` 保留为可选兼容接口。
- 设备租约是平台并发控制状态。平台确认可以安全替代过期租约后，通过 `lease_resolution` 返回有效租约，后续沿用已成功的构建、probe 和真实返回。任务状态未知、设备忙或需要对账时，先依据真实 job_id 与诊断完成对账，不循环换租。
- 先用 `platform_list_hardware_api_templates` 选择语义和 profile 相容的模板，再以精确 ID 读取。Agent Adapter 未直接展示专用工具时，通过 `platform_call_tool` 传入同一工具名与参数。保留稳定脚手架，替换当前计算核心、输入合同、CPU oracle 和比较逻辑。
- 按 API 暴露层选择官方测试承载。只有真实 runner 报告才能声称使用了 xDevice/Hypium/HATS；没有 runner 时可做 `standalone_fallback`。
- 首个实验只闭合最小未知量：确定性输入、CPU/software reference、候选路径、结果比较和明确退出码。功能等价后再测代表性规模和性能。
- 每次只依据真实 profile、编译、链接、上传、stdout/stderr 或设备观察做最小修订。
- 任务完成、方向被证伪、环境明确不可执行、用户停止或缺少用户专有输入时结束。

最终分别报告模板/承载、构建、部署、设备执行、功能等价、目标硬件参与、热点集成、性能/功耗和限制。需要框架选择细节时读取 `references/official-test-frameworks.md`。
