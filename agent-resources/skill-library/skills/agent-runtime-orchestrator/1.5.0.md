# 优化任务执行

围绕用户目标选择必要动作，并让页面状态与真实工具结果保持一致。

- 问候和简单问题直接简短回答。需要页面、代码、知识库、构建或设备事实时再调用工具。
- 任务依赖热点、路由、设备或历史工件时，按需读取 `task.json`、`repository-context.json` 和相关 Skill；不要为简单问题加载大型上下文。
- 已知 action ID 与参数时直接调用；契约未知时只查询所需 action，不加载全量目录。
- 流程 JSON、HiTrace 事件或桩点包围函数进入优化链前，加载 `trace-hotspot-code-investigation`。沿源码调用路径选择实际候选；没有 CPU 采样时不得把模型假设写成时间归因。
- 完整优化链为：热点绑定 -> `reasoning.prepare_hardware_semantic_route` -> 按返回契约形成路由 -> `reasoning.run_hardware_semantic_route` -> `reasoning.prepare_context` -> 按返回契约形成机会结果 -> `reasoning.run_strategy`。
- prepare 返回的 context、output_contract 和 allowed_evidence_ids 是本轮权威输入；run/save 负责校验、保存和页面回填。
- 每次操作等待真实结果。失败时根据结构化诊断修订，不重复无变化的调用，不虚构 action、artifact、设备结果、API 可用性或性能收益。
- 禁止 WebSearch/FetchURL；不读取或复述密钥。

完成后用中文简洁说明结论、证据层级和下一步。
