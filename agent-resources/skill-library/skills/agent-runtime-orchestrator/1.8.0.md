# 优化任务执行

围绕用户目标选择必要动作，并让页面状态与真实工具结果一致。

- 问候和简单问题直接回答。页面命令已点名 MCP 工具时立即调用；工具返回的是本轮权威上下文和契约，不要先搜索平台源码、Action ID 或全量 Skill。
- 找不到所需 Skill 时，先读取 `$HETERO_AGENT_SKILL_ROOT/<skill-id>/SKILL.md`；若该变量不可用，则查找当前工作区 `.agents/skills/<skill-id>/SKILL.md`；仍不存在时，遵循当前目录层级的 `AGENTS.md` 及 Agent 框架自身的 Skill 发现约定。
- 目标含糊或需要当前页面概况时调用 `platform_get_task_context`；只有工具结果要求补充细节时才读取 `task.json`、`repository-context.json` 或相关 Skill。
- 任务涉及模块职责、业务流程、调用路径、热点 callee、状态/数据流或 API 实现时加载 `code-context-retrieval`。已有语义图谱用于缩小源码范围，最终关系仍需回读源码确认。
- Trace 事件或桩点包围函数进入优化链且真实热点尚未确认时，加载 `trace-hotspot-code-investigation`；用户粘贴代码和已确认源码候选不加载该 Skill。
- 完整优化链为：热点绑定 -> `reasoning_prepare_hardware_semantic_route` -> 按返回契约形成路由 -> `reasoning_run_hardware_semantic_route` -> `reasoning_prepare_context` -> 按返回契约形成机会结果 -> `reasoning_run_strategy`。
- prepare 返回的 context、output_contract 和 allowed_evidence_ids 是本轮权威输入；run 工具负责校验、保存和页面回填。
- 每次操作等待真实结果。失败时依据结构化诊断修订，不重复无变化的调用，不虚构工件、设备结果、API 可用性或性能收益。
- 禁止 WebSearch/FetchURL；不读取或复述密钥。

完成后用中文简洁说明结论、证据层级和下一步。
